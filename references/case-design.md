# 用例与判断依据

## 需求到用例
逐条提取可验证规则并保留来源定位。规则冲突登记 requirements，不选择更容易通过的版本。优先风险：资金、身份、数据损坏、重复外发、核心不可用、不可回滚动作。

每个用例：ID、关联需求、风险、层级、前置、操作、独立断言、证据、超时、清理。每个断言有ID；执行记录逐项说明 passed/failed/not_evaluated。

## 选择方法
| 方法 | 用途 | 误用 |
|---|---|---|
| 等价类 | 合法/非法输入类别 | 只选一个正常输入 |
| 边界 | 长度、金额、时间上下限及邻点 | 忽略精度、包含/不包含约定 |
| 判定表 | 多条件规则 | 默认所有组合可达 |
| 状态转换 | 合法和非法前驱/后继 | 只测成功终态 |
| 组合测试 | 限制高维输入组合成本 | 将成对覆盖当全部组合证明 |
| 属性测试 | 对广泛输入验证不变量 | 性质直接调用被测函数计算预期 |
| 差分 | 独立实现或新旧版本比较 | 两个实现同源就视为独立真值 |
| 变形 | 缺少直接预期时验证输入变换关系 | 未证明关系适用就做断言 |

## 判断依据
优先验收标准、契约、状态规则、业务不变量和独立计算。历史实现可能有缺陷；快照只能证明变化，变化是否正确仍需规则。预期金额应使用独立明确规则和适当精度，不复制业务实现。

## 分层
单元测纯逻辑与分支；组件测局部边界；真实集成测事务/锁/协议交互；接口测契约和业务副作用；端到端测关键用户路径。避免同一断言在所有层重复却遗漏底层失败；使用能揭示风险且维护成本合理的层级。

## 典型订单矩阵
正常、金额边界、优惠券归属/有效期、库存不足、非法数量、无认证、跨用户订单、重复幂等键、并发抢库存、超时后重试、消息重复、支付回调伪造或重复、取消后状态、失败补偿。按实际范围取舍。

顺序重复不等于并发重复；成功响应不等于无重复副作用；检查“被拒绝”时也检查未发生未授权写入。

## 终止与维护
穷举不可行时记录抽样、组合策略及未覆盖风险。基于新缺陷增加有区分力的用例，不机械扩充重复用例。变更产品代码后重测影响范围，不用旧结果代替当前结果。
