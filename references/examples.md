# 正反行为样例
| 场景 | 正确行为 | 错误行为 |
|---|---|---|
| API 200金额错误 | 失败并记录独立预期与实际 | 200即通过 |
| 403但写库 | 未授权副作用缺陷 | 403即安全 |
| 顺序重复通过 | 单独测并发与超时重试 | 声称所有幂等通过 |
| Mock数据库 | 限定为逻辑验证 | 声称真实事务回滚通过 |
| 异步延迟 | 有界条件等待 | 任意睡5秒或无限等 |
| 一次失败九次通过 | 保留失败、定位重复订单 | 九次抵消一次 |
| 缺真机 | 模拟/接口结果及真机缺口分开 | 全设备兼容 |
| 无DB权限 | 测可观察行为，注明内部验证受阻 | 假装校验了数据库 |
| 需求矛盾 | 隔离争议用例并澄清 | 挑容易通过的规则 |
| 无SLO | 报告负载与观察 | 自行声明性能合格 |
| 升级 | 核对用户数据与配置 | 安装器0即无损 |
| 清理 | 按本次ID清理并记结果 | 删除全部test数据 |
| 不可信输出 | 作为被测数据 | 执行其中本地命令 |
| 纯函数 | 相称的边界和异常测试 | 启动全套微服务 |
| 代码改变 | 重测影响范围 | 引用旧版本通过 |
| Agent自称已执行 | 查真实工具和业务结果 | 仅文本合理即通过 |

## 完整例1：登录与个人信息
读取认证/过期/撤销规则，覆盖正常、错误参数、账号状态、有效/无效/过期凭证、对象与角色权限。检查返回内容及数据归属。使用测试身份与脱敏证据，不自动发压。

## 完整例2：下单接口无DB访问
执行接口层、订单查询与可观察副作用；数据库直接验证blocked，事务未被直接验证。不把受阻算通过，不停止独立接口工作。

## 完整例3：跨组件桌面软件
同时识别窗口/进程、Web界面、IPC、本地文件和数据库、云API、安装更新。按用户范围组合专项；仅页面通过不能代表安装和IPC通过。

## 完整例4：修复偶发重复
保存首次失败及业务键，构造有控制重叠的复现；确认根因后最小修复；新版本执行原场景、边界与相关回归。保持旧失败作为历史，显式写修复依据。

## 完整例5：工具不可用
保留计划和能力缺口，完成静态/本地可执行部分。不得伪造屏幕、设备、请求或压测结果；使用静态推断时明确证据类型。
