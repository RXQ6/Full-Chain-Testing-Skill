# Android / iOS
输入：构建、系统、设备、账号、分发与控制能力；区分模拟器和真机。
- 冷/热启动、前后台、进程终止、旋转和适用状态恢复。
- 权限申请、拒绝、撤销；深链、通知和系统交互按功能验证。
- 断网、切网、弱网、超时后的反馈、重试和重复副作用。
- 安装、覆盖升级、数据保留；清数据/卸载使用授权测试设备。
- 按用户选系统、尺寸、输入法及可访问性矩阵。
- 性能、耗电、内存和崩溃明确测量条件。
证据：构建号、设备系统、步骤、设备日志、截图及服务端数据。缺真机报告缺口，不以API替代。
正：真机切网后只有一笔订单。负：接口通过即客户端弱网通过。

## 执行记录与反证步骤
1. 固定被测版本、目标平台、输入和起始状态；先复现一条最小合法流程。
2. 选择本专项最重要的失败边界，登记需求ID、操作、独立预期和可观察副作用。
3. 复用项目已有工具：界面使用现有UI工具，库/脚本使用语言测试入口，设备使用台架/协议客户端。工具不可用时不要假造运行。
4. 对隔离副本施加一个已知违例，核对原断言失败；无法安全注入时保留验证局限。
5. 保存实际步骤、输出和状态差异，清理本次资源。模拟环境、平台和设备型号写入结论。
反例：只记录工具退出码而未验证用户结果；截图看似正常但数据错误；恢复后重复执行外部动作。三者均不能作为通过。
