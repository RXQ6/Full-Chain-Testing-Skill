# CLI / 脚本 / SDK / 文件
CLI：参数、stdin/stdout/stderr、编码、退出码、超时、取消和部分输出。契约要求的非零退出可以正确；区分被测命令与测试运行器异常。
SDK：公共API、异常、默认值、同步/异步、并发、资源释放和兼容；使用消费者程序，导入成功不等于正确。
文件/媒体：空、损坏、截断、格式、编码、大文件、路径、权限、覆盖和中断；核对内容、结构及可读性。恶意输入不赋予执行权限。
证据：命令、参数摘要、退出码、输出、属性和内容校验；不覆盖真实文件；只报告已执行的平台。
正：非法输入按约定失败且无残留输出。负：文件存在就判内容正确。

## 执行记录与反证步骤
1. 固定被测版本、目标平台、输入和起始状态；先复现一条最小合法流程。
2. 选择本专项最重要的失败边界，登记需求ID、操作、独立预期和可观察副作用。
3. 复用项目已有工具：界面使用现有UI工具，库/脚本使用语言测试入口，设备使用台架/协议客户端。工具不可用时不要假造运行。
4. 对隔离副本施加一个已知违例，核对原断言失败；无法安全注入时保留验证局限。
5. 保存实际步骤、输出和状态差异，清理本次资源。模拟环境、平台和设备型号写入结论。
反例：只记录工具退出码而未验证用户结果；截图看似正常但数据错误；恢复后重复执行外部动作。三者均不能作为通过。
