# 数据库 / 缓存 / 消息 / ETL
数据库：约束、空值、精度、事务回滚、隔离、锁和并发更新；真实事务需真实测试依赖。迁移核对键、内容、关系、约束，不只行数。
缓存：命中/缺失、过期、更新、不可用、跨实例及租户键隔离；区分退化和业务错误。
消息：重复、乱序、延迟、重投、积压、死信和恢复；重点检查副作用成功但ACK前中断。消息确认不等于业务仅执行一次。
ETL/调度：粒度、窗口、时区、水位、迟到、缺失、重复、关联丢失、空值及模式漂移；补跑核对覆盖/去重；任务退出0不等于数据正确。
证据：计数、业务键、聚合、样本差异、消息ID和水位。只处理本次隔离数据，大查询/恢复/迁移遵守资源与授权。
正：按键和金额核对迁移。负：行数相同就认定无误。

## 数据构造与不可观测降级
工厂：按run_id/worker_id生成业务键与账号，显式声明初态；测试后按ID清理，不按模糊名字删除。
快照：使用隔离测试快照，记录版本/校验值和恢复范围；不把真实生产副本直接提交。
脱敏样本：只保留触发规则的字段，替换身份、联系方式、地址和Token；关联键应一致替换，保留统计性质而非可识别细节。
边界数据：空、重复、迟到、缺关联、极端金额和模式变化分别造样，不靠随机碰运气；固定种子仅用于复现，不能把它当广泛覆盖。
无DB时依次用业务查询、审计、下游Mock出口和稳定业务键核对，在约定deadline内交叉确认。时间差只能支持延迟观察，不能证明内部回滚；看不到的副作用仍是不确定。无消息管理权限可比较业务最终状态与幂等记录，不宣称消息投递机制本身已验证。
