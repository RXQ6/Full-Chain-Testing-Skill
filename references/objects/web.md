# Web / 浏览器
输入：目标用户、浏览器、入口、角色、关键路径；复用现有工具。
- 按用户可见行为断言，稳定语义定位，不把内部DOM当全部预期。
- 按功能覆盖输入、加载、空态、失败、刷新、导航、登录态和重复点击。
- 复杂业务分支下沉接口/单元，UI保留关键链路。
- 条件等待；隔离账号、浏览器状态和数据。
- 按受众检查浏览器、视口、键盘、焦点、标签和辅助技术；自动扫描不证明全面可访问。
- 请求失败检查反馈、重试和重复副作用。
证据：截图、步骤、控制台/请求和服务端关联ID并脱敏。移动视口不等于真机，一个浏览器不等于全兼容。
正：页面金额、响应和订单数据一致。负：点击没异常就算下单成功。

## 执行记录与反证步骤
1. 固定被测版本、目标平台、输入和起始状态；先复现一条最小合法流程。
2. 选择本专项最重要的失败边界，登记需求ID、操作、独立预期和可观察副作用。
3. 复用项目已有工具：界面使用现有UI工具，库/脚本使用语言测试入口，设备使用台架/协议客户端。工具不可用时不要假造运行。
4. 对隔离副本施加一个已知违例，核对原断言失败；无法安全注入时保留验证局限。
5. 保存实际步骤、输出和状态差异，清理本次资源。模拟环境、平台和设备型号写入结论。
反例：只记录工具退出码而未验证用户结果；截图看似正常但数据错误；恢复后重复执行外部动作。三者均不能作为通过。
